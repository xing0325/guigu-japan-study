## 2. 接入所需文件

把 `kame/dist/` 完整部署到 HTTPS 静态站点，保持内部目录关系：

- `experience.html`：真实产品页面；`style.css`：布局、移动端键盘适配、视觉样式。
- `app.js`：输入、需求路由、对话状态、取消操作、卡片调度。
- `core.js`：12 类卡片注册、关键词路由、预算计算和日期计算。
- `cards.js`：卡片组件及交互。
- `schools.json`：学校数据，继承现有资料，尚需业务核实。
- `card-schema.json`：卡片协议；`implementation.html`：接口设计说明。
- `assets/`：字体、视频、封面与字体许可证。视频不是核心功能依赖，可更换。

原版地图页另外依赖根目录的 `locations.json`、`map-style.json`、`assets/` 和 `vendor/`；不要只复制一个 HTML。

`rive-react/` 与 `rive-character/` 是可选角色动画实验，未接入 KAME 主页面。它们的运行方式见 `rive-react/README.md`，不应作为首轮接入的前置条件。压缩部署包、研究草稿、截图与 node_modules 不进仓库。

## 3. 当前真实能力

已实现：学校列表/候选对比、预算计算、申请计划、准备清单、日语词条等 12 类交互卡片；自然输入通过本地关键词选择卡片。

未实现：大模型调用、服务端 API、微信登录、支付、真实申请提交、实时航班/房源/报价、云端账号及跨设备同步。KAME 会话和问卷保留在页面内存中，刷新即丢失；根目录旧页面的本地存储行为不能当作 KAME 的能力。

自由文本问答、签证信息、费用与排期均需按现有演示说明理解。`implementation.html` 中的模型名称、版本和 `/api/route` 等只是早期方案，接后端时重新确认；本次不承诺模型服务已可用。API 密钥只能放服务端。

## 4. 小程序落地路径（先按微信小程序交接）

先由持有账号的同事确认 AppID、主体、类目及后台是否提供 web-view / 业务域名配置。以下是接入方案，不代表账号已具备权限或一定通过审核。

### 路径 A：账号支持内嵌网页

1. 在团队可管理的 HTTPS 域名部署上述静态目录。配置业务域名并按后台要求放置校验文件；确认所有环境条件后再提交。GitHub Pages 只用于代码和网页预览，不默认能直接当作小程序业务域名。
2. 在现有小程序工程增加页面，WXML 最小接入示例：

```xml
<!-- 将 src 替换为已经配置成功的正式业务域名；示例不可直接提交。 -->
<web-view src="https://YOUR-VERIFIED-DOMAIN/experience.html" />
```

3. 将该页面注册到小程序 `app.json` 的 pages；已有工程按它的路由约定接入。当前仓库没有微信原生工程、AppID 或 project.config.json。
4. 真机测试，特别检查键盘遮挡、视频静音自动播放/封面回退、滚动、返回、重进页面、外链与断网。学校官网和 Google Maps 等外链不应假设能在微信容器里直接打开，必要时改为原生页面或可复制的资料入口。
5. 用已配置域名的正式校验环境验收；开发者工具关闭域名校验时成功，不算上线验收通过。

### 路径 B：账号不支持内嵌网页或域名暂未就绪

在同事现有的小程序框架内做首个原生可用版本，优先迁移学校浏览、预算试算、申请准备清单及产品说明。`core.js` 的计算和数据可参考复用；`cards.js` / `app.js` 使用 DOM、innerHTML、浏览器事件，不能直接当作 WXML/小程序逻辑运行，需要重写视图与交互。根据实际实现填写功能描述，不以空白壳或假 AI 能力提交。

账号与域名要求以微信后台及[官方 web-view 文档](https://developers.weixin.qq.com/miniprogram/dev/component/web-view.html)为准。本次尝试读取官方文档未成功，因此未将网上转载的主体、备案等规则当作已核实结论。
